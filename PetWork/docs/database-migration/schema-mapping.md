# SQL Server → PostgreSQL şema eşlemesi

Hedef uygulama şeması `petwork` olarak seçildi. Supabase'in `auth`, `storage`, `realtime`, `extensions` ve diğer sistem şemalarına dokunulmaz. `petwork` varsayılan Data API şeması değildir; mobil istemci bu aşamada DB'ye doğrudan değil .NET backend API'sine bağlanacaktır.

| SQL Server | PostgreSQL | Uygulama |
|---|---|---|
| `int IDENTITY` | `integer GENERATED BY DEFAULT AS IDENTITY` | Kaynak ID açıkça yazılır; aktarım sonunda sequence en büyük ID'ye ayarlanır. |
| `int` | `integer` | Değer aynen korunur. |
| `bit` | `boolean` | `0/1` → `false/true`. |
| `nvarchar(n)` | `character varying(n)` | Karakter sınırı karakter sayısı olarak korunur. |
| `nvarchar(max)` | `text` | Unicode/Türkçe metin kayıpsız UTF-8 aktarılır. |
| `datetime2` olay zamanı | `timestamp without time zone` | Kaynak saatler `DateTime.Now` ve saat dilimsiz olduğu için ilk aktarımda saat kaydırılmaz. |
| `Pets.DateOfBirth datetime2` | `date` | Doğum tarihi yalnızca takvim tarihi olarak saklanır. |
| SQL Server `CI` kullanıcı/e-posta eşitliği | PostgreSQL `citext` | `Username` ve `Email` büyük/küçük harf duyarsız kalır. |

`citext`, Supabase tarafından sunulan PostgreSQL uzantıları arasındadır ve PostgreSQL migration'ı tarafından oluşturulur. Kaynakta büyük/küçük harfe göre çakışan kullanıcı adı veya e-posta grubu bulunmadığı doğrulanmıştır; hedefte iki alan için benzersiz indeks oluşturulur.

PostgreSQL timestamp hassasiyeti mikrosaniye (6 ondalık basamak), SQL Server `datetime2` hassasiyeti ise 100 nanosaniyeye (7 basamak) kadar çıkabilir. Aktarım bu nedenle yalnızca son 100 nanosaniyelik basamakta en fazla 0,9 mikrosaniye kaybedebilir. Doğrulama aracı iki tarafı ortak mikrosaniye hassasiyetinde karşılaştırır; tarih veya saat dilimi kaydırması yapmaz.

## Kaynaktan korunan DB default'ları

- `Users.IsAdmin = false`
- `Diseases.ViewCount = 0`
- `Diseases.PublishDate = 0001-01-01 00:00:00`
- `Pets.PetType = ''`
- `Recipes.Description = ''`
- `Recipes.PreparationTime = 0`

Model sınıflarındaki diğer C# property initializer'ları kaynak DB default'u değildir ve PostgreSQL şemasına DB default'u olarak eklenmemiştir.

## Tablo ve ilişki stratejisi

On uygulama tablosu (`Users`, `Badges`, `BadgeUser`, `BlogPosts`, `Diseases`, `Guides`, `Pets`, `Questions`, `Recipes`, `Answers`) aynı adlarla ve kaynak null kurallarıyla `petwork` şemasında oluşturulur. Foreign key silme davranışları kaynak envanterindeki `CASCADE` / `RESTRICT` karşılıklarıyla korunur.

SQL Server migration'ları `Migrations/` altında kalır. PostgreSQL migration'ları `Migrations/PostgreSql/` altında ve `PostgresPetWorkDbContext` ile ayrıdır. SQL Server `__EFMigrationsHistory` satırları PostgreSQL'e veri olarak taşınmaz.
